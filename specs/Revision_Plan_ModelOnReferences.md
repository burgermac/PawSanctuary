# Revision plan — model PawSanctuary on the references

**Status: 18 Nov 2026. Approved direction (D14, Alignment Plan). No code written yet.** This is the work list behind `Triage_ModelOnReferences.md`. The live checklist the owner follows is the **PawSanctuary Revision Tracker** page (same task ids as below); the project manager keeps both in step.

## Rules for everyone working from this plan

1. **D14 is the authority** for the order rule. Read it and `Triage_ModelOnReferences.md` §2.1, §2.9 first. Where a spec seems to conflict with the code, check the code and say so.
2. **One task per worker session.** Branch off `main` (never off `feat/chain-viewer-owned-badges`, which belongs to another piece of work), commit, open a PR, stop. The owner merges. Nothing is pushed to `main`.
3. **Specs before code** for every item marked *spec first*. A spec is written cold (self-contained), lists what is out of scope, and names its tests. The owner sees specs for W1, W5 and W7 before any build.
4. **Persisted shapes:** any change needs a schema bump (currently v45 to v46 or later), a migration, and a `PersistenceTests.swift` case. Row W5 changes saved tier indices.
5. **Economy changes** are checked against `EconomySimulation` and `testDemandSupplyRatioMatchesTheTargetCurve` before they ship. D7 (no monetization in session one) and D9 (retention outranks monetization) still bind.
6. **Where a reference value is unmeasured, do not invent it.** Mark the task blocked on the matching recording (`Recording_Guide.md`, ids R1 to R9) and move on.
7. Work in parallel only when tasks touch different files. `MergeBoardViewModel.swift` and the order code are one lane: W1 tasks run one at a time.
