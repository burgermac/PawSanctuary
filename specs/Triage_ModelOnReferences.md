## 0. The proposed standing rule

The Alignment Plan's own objective line already reads "bring PawSanctuary's gameplay psychology into line with the three measured reference titles", so this is a clarification of how decisions are read, not a new direction:

- **A difference from the references needs a recorded reason that survives re-reading.** "It is cheaper" or "no data yet" justify *sequencing* a change, not keeping the difference for good.
- **Where the two references disagree with each other, there is nothing to copy.** Those rows need an owner pick (§3).
- **Copying a reference trait is not automatic when it works against D7 or D9.** Those rules were adopted because of the references' data (D7 from Gossip Harbor's silence), so they stay unless the owner says otherwise.

If you accept this, it should go into the Alignment Plan as one short entry. I have not written it there.

## 2. The rows that need explaining

### 2.1 Order fulfilment (row 2): the clearest mechanic difference

- **The original reason was thin.** The code comment that fixed the rule says the references fulfil by dragging an item onto the order. Neither does: Gossip Harbor shows a Serve button and Travel Town a green GO button once the held items satisfy the card (§2.9), so the comment's premise is wrong for both. The comment's stated reason is about what the order card's tint should promise, not about the economy.
- **Half the game already does it the reference way.** The daily hand-in tasks read held creatures live off the board (`boardTaskCensus`).
- **Why it is not a one-line change.** Order demand is sized on production events, and `EconomySimulation` and `testDemandSupplyRatioMatchesTheTargetCurve` are tuned around that. D12 says any change must be re-checked against the Phase 2 targets. A held-item rule consumes surplus items instead of crediting a side effect, which moves demand.
- **What converging buys.** A Dog Tag store purchase would fill an order directly, which makes D3's "highest-intent conversion" reason true for the store, not just the wildcard.
- **Both references now observed** (§2.8, §2.9), and they agree, so there is one target behaviour to model, not a choice between two. The order is: update `EconomySimulation`, then the rule, then `OrderFulfilmentRuleTests`.

### 2.2 Twelve tiers versus fifteen (row 3): the biggest economic rework

- **The 12 came from PawSanctuary's own cap, not from the references.** Phase 2b says orders were capped at tier 9, which left stages 10–15 outside the loop. The references keep 14–15 tiers and ask for mid-chain items in orders (Travel Town: "1–2 specific items at mid-chain tiers"), so the top tiers are aspirational, not order targets.
- **What reverting costs:** 45 tier names were deleted from source (old indices 9–11 in each of 15 families; recoverable from history), the matching art, and a Phase-2-scale retune. Saves store tier indices, and the deletion renumbered old 12–14 to 9–11, so restoring needs a migration and a `PersistenceTests` case.
- **Dependency:** row 2 first. A held-item rule plus mid-chain order targets is what makes long chains workable.
- **Not verified:** whether the art for the deleted tiers still exists in the asset catalogue.

### 2.3 Discovery collection (row 5)

Both references have one. A first Gossip Harbor check on 18 Nov (§2.8) saw no reward when a new tier was made, which leans toward D13's hold but is one observation on a level-1 profile. D13's reasons (unsized Dog Tag faucet, no per-chain state) stand. The reward-free `?` slots remain the safe first step.

### 2.4 Story and characters (row 8)

The references disagree: Gossip Harbor is story-led, Travel Town gives orders 17 characters but showed no dialogue. The cheapest convergence is Travel Town's: named, portrayed order characters. PawSanctuary's `AdoptionFamily` has an SF Symbol, not a portrait, so that step is an art task. A Gossip Harbor-style story layer is the largest single item in this document and should follow, not precede, the portrait step.

### 2.5 Chores (row 9)

D10's reasons were PawSanctuary-specific (coins pinned to the map's 55–70-day build-out, XP gating the wall) and its third reason was that nothing was measured. That third reason is the one to fix: a played Gossip Harbor session past the point where chores appear would give costs, XP and counts. Without them a chore system would be invented, not modelled.

### 2.6 Events (rows 10 and 11)

Matching the references' cadence is an operating-cost question first. Each calendar is currently a spec, tasks and a release. The smallest safe step is the comparison's §5-B option 2: event dates, thresholds and reward tables in a remote JSON file with the built-in copy as fallback. That touches persistence-adjacent code (event ids key saved state), so `CLAUDE.md` rule 5 applies and it needs its own sprint and migration review. D5's three-event cap was a guard against feeding the lattice without telemetry; it should be revisited together with row 12, not before.

Gossip Harbor's level-5 live-ops layer was last measured in July on v3.94.5, eight releases older than the installed 4.12.0. Re-measure before copying it.

### 2.8 Measured 18 Nov 2026: Gossip Harbor 4.12.0, fresh profile

About ten minutes at level 1 (100 energy, 2 coins, 0 gems), driven through the macOS app. Limits: one profile, one chain merged, screenshots can lag an action.

- **Chain viewer.** Opened from the info bar's "i" button, and also by tapping an order. It shows every tier of the chain with the held ones lit, the rest as `?`, the current tier highlighted, and a "Generated by:" footer naming the producing generator. This confirms the July description on the installed version.
- **Owned-count badge.** A green "1" on Beginner's Bread, of which I held one. Confirms the badge the chain-viewer spec adopts.
- **Chain lengths and order targets.** Cut Potatoes shows 7 slots. Half a Ham Sandwich shows 15 (4+4+4+3). The first order asked for Half a Ham Sandwich, level 8 of 15, so Gossip Harbor's orders do ask for mid-chain items. That is the premise row 3 (§2.2) rests on, now seen in Gossip Harbor and not only in Travel Town's config.
- **First-creation reward: none seen.** Two flour sacks merged to Proofed Dough, then two of those to Beginner's Bread (level 3), which the viewer then showed as discovered. No popup appeared and coins (2), energy (100) and gems (0) did not change across three captures. Not conclusive: a later tier, or a feature unlocked at a higher level, could still pay.
- **Not measured:** chores, level-5 live-ops, and anything past level 1.
- **Tooling note.** The viewer's "i" button ignores the accessibility press; a raw press and release (the drag tool with two nearby points) opens it. Drag merges work with a multi-point path.

### 2.9 Measured 18 Nov 2026: Travel Town order delivery, from a recording

Source: `ScreenRecording_08-22-2026 21-30-06_1.MP4`, 28 s, player level 54, read with `scripts/refvideo.swift` (contact sheet at 1 s, then native-resolution crops of the order rail at 0.4 s steps around 2–4.4 s). A live attempt on the installed app failed (its window could not be captured), so this is the only Travel Town evidence for the mechanism. The clip does not show a finger, so that a tap on GO caused the delivery is inferred from the sequence.

- **The card shows what you hold.** Each required item sits in a slot. A slot is green when that item is on the board, and the matching board tile is highlighted green. The live app on 18 Nov also showed a green slot on a two-item order (one green, one not), consistent with this.
- **A green GO button appears on the card once every required item is held.** At 2.4 s the first order (pancakes and a hairbrush, both green) carries it. A card with an unfilled item (a milkshake) shows no GO.
- **Delivery is a button, not a drag.** Within about 0.8 s of GO the button blanks, the card's items lift off it, and rewards fly out in separate streams: coins, popcorn tokens and a starfish +1 (the earring pill is not seen leaving in these crops). `Spec_TravelTownReview_Draft.md` §2 already describes the full five-currency payout.
- **An unfilled slot carries a red shopping-cart badge.** The milkshake slot on the third card shows one, so the order itself offers a way to buy the missing item. That is the contextual buy path D13's "See in store" shortcut is modelled on, and it sits on the order, not only in the chain viewer.
- **Not seen in the recording, ruled by the owner 18 Nov 2026 from their own play of the game:** a partly filled card delivers nothing and shows no button; delivered items leave the board; held items show in a muted highlight and the highlight turns more vivid once every required item is present. These are the target rules in D14.
- **Still not seen:** the price behind the cart badge; which copy is taken when several are held; how one item is shared between two orders.

**Effect on row 2:** both references fill orders from held items through a button on the card. The code comment behind D12 describes a drag that neither game uses, and PawSanctuary's rule differs from both.
